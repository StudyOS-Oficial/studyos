1. Entender

UN CASO DE USO NO ES UN PROMPT
Es una solución a un problema de trabajo. El prompt puede formar parte de ella, pero el caso de uso también necesita entradas, proceso, salida, revisión, límites y métrica.
ANTES
Describe cómo haces hoy la tarea: pasos, tiempo aproximado, problemas y resultado.
DESPUÉS
Define qué parte hará la IA, qué información recibirá, qué producirá y dónde intervendrá una persona.
MÉTRICA
Elige una medida sencilla. Por ejemplo: tiempo de 90 a 45 minutos, revisiones de 4 a 2, errores detectados, volumen procesado o tiempo de respuesta.

2. Diseñar

PASO 1 · PROBLEMA

¿Qué quieres mejorar?

Describe la tarea actual y por qué merece la pena cambiarla.

PASO 2 · ENTRADAS

¿Qué necesita el proceso?

Enumera documentos, datos, instrucciones y contexto necesarios.

PASO 3 · IA

¿Qué hará exactamente?

Define una función concreta: extraer, resumir, clasificar, redactar, comparar, analizar o proponer.

PASO 4 · CONTROL

¿Qué revisará una persona?

Define los criterios de aceptación y qué errores deben detener el proceso.

PASO 5 · SALIDA

¿Qué recibiremos?

Especifica formato, estructura y condiciones que debe cumplir el resultado.

PASO 6 · MÉTRICA

¿Cómo sabremos si funciona?

Define una medida antes de probar. Sin línea base, es difícil demostrar mejora.

4. Proyecto de Semana 1

Entrega: un documento de una página con estos siete apartados: 1) Problema · 2) Proceso actual · 3) Oportunidad de IA · 4) Flujo IA + revisión humana · 5) Riesgos y límites · 6) Métrica · 7) Primer experimento.

Después prepara una prueba con datos ficticios o no confidenciales. No busques todavía automatizar: primero demuestra que el flujo funciona manualmente.

💡 La primera versión no tiene que ahorrar una hora. Tiene que demostrar que el proceso funciona y que puedes medirlo.
⚠️ Si el caso afecta a información sensible o decisiones críticas, valida primero las políticas de tu organización. El proyecto debe poder probarse de forma segura.
