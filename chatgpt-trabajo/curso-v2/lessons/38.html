Inputs y outputs: diseñar los límites del sistema

La calidad de una herramienta depende en gran parte de lo que permite entrar y de cómo obliga a estructurar lo que sale.

Objetivo: definir contratos claros entre usuario, herramienta e IA.

1. APRENDER · El contrato de datos

INPUT VÁLIDO
PROCESAMIENTO
OUTPUT
VALIDACIÓN

Un input puede necesitar formato, longitud, campos obligatorios o límites. Un output puede necesitar secciones obligatorias, etiquetas o valores permitidos.

2. HACER · Especificación

Define el contrato de entrada y salida de esta herramienta:

OBJETIVO:
[...]

Para cada INPUT indica:
- Nombre
- Tipo
- Obligatorio/opcional
- Ejemplo válido
- Ejemplo inválido
- Validación necesaria

Para el OUTPUT indica:
- Campos obligatorios
- Formato
- Longitud aproximada
- Qué hacer si falta información
- Qué debe revisar una persona

3. VER · Evitar el “texto libre” cuando no hace falta

Si necesitas una fecha, pide una fecha. Si necesitas una categoría, define las categorías. Cuanto más claro sea el contrato, menos ambigüedad tendrá el sistema.

4. EXPERIMENTAR

Define cinco inputs de tu herramienta y escribe un ejemplo válido y uno inválido para cada uno. Después decide qué debería ocurrir cuando el usuario introduce un valor incorrecto.

💡 Diseñar inputs es también diseñar prevención de errores.
